# 师傅行程与订单内联系

状态：开发试用实现，已验证服务端双向消息、坐标更新和撤销；非生产上线。2026-09-11。

## 本轮交付与运行边界

入口：启动开发服务，商户进入排程，确认预约后点击「建立行程與聯絡入口」，分别打开客户和师傅链接。师傅点击出发后可自愿开启定位。入口保存在当前商户标签页会话中，刷新可恢复。

新增 `src/journeys/runtime.ts`、服务端通信接口、`/journey` 页面和排程入口。复用 ScheduledBooking 的 tenant/vertical/job/worker/customer 绑定和已有会话消息字段；不修改预约状态机。「取消本次行程」不是取消预约。

角色由服务端随机不透明链接决定，不接受客户端自报角色。链接是 bearer capability：持有者可以访问，不等于已验证真实身份；不得公开分享。接口通过 POST 传令牌，链接 fragment 读取后清除，外部地图不传 referrer。共享默认关闭，授权最长一小时，坐标最多展示六十秒，到达、取消行程、完成或撤销即删除坐标并拒绝旧授权上传。地图精确坐标交由 OpenStreetMap 显示，界面已提示。

当前仅 NODE_ENV=development 启用。预约来自既有浏览器候选仓库，因此不得开放生产创建入口。服务端为单进程内存，入口四小时有效，重启/HMR 后失效；过期记录在下一次请求清理。最多一百个行程、每单二百条消息，不是持久数据库或跨实例服务。正式订单取消同步、已认证参与者、耐久消息/撤销记录、连接限流、后台定位仍未交付。

## 用户需求

客户预约师傅后，可以查看师傅是否正在前往现场、在地图上查看实时位置，并与师傅实时联系。师傅可以自主开启和关闭位置共享。该功能不依赖 WhatsApp。

## 产品行为

- 客户预约详情增加「师傅行程」卡片，显示待出发、已出发、已到达、服务中、已完成状态。师傅明确点击「出发」后进入在途状态；单纯检测到手机移动不构成已出发证据。
- 师傅订单详情提供「向本单客户共享位置」开关，默认关闭。师傅开启并授予设备定位权限后开始上传；可随时关闭。共享仅面向当前订单的客户。
- 客户地图展示最近位置、定位精度、最近更新时间；位置过期或网络中断时显示「位置暂未更新」，不把旧坐标表现为当前实时位置。没有共享时明确显示「师傅未开启位置共享」。
- 关闭、取消订单、订单结束或共享授权到期后，服务端停止接受该授权的位置上传，客户端停止定位监听，客户地图撤去位置。迟到或重放的数据不能重新开启共享。
- 第一阶段通过订单内文字会话联系师傅，显示发送失败与重试状态；客户与师傅的设备能相互收到新消息。仅有发送回执时不得显示「已读」。定位关闭不影响文字联系。
- 语音、视频、电话号码披露、路线与预计到达时间是后续能力；预计到达时间需接入路线服务，不能以直线距离伪装交通预测。

## 既有模块与缺口

复用 `src/scheduling/` 的预约与 Worker、`src/privacy/` 的订单身份和授权、`src/conversations/` 的会话基础；行程状态附属于既有订单，不复制预约状态机。

当前私隐 capability 不包含师傅位置，consent record 仅覆盖客户地址，不能将客户地址授权借用为师傅定位授权。需要增加由已认证师傅授予、绑定 tenant/vertical/job/worker/customer、可撤销且会过期的位置访问授权。

当前已验证对话使用浏览器 localStorage；同一浏览器跨标签同步不代表客户手机与师傅手机互通。上线需要师傅认证、服务端订单参与者授权、位置上传与订阅、消息持久化与实时传输。精确坐标不得放入公共订单视图或模型上下文。

移动端后台定位需单独验证。网页前台定位不能作为锁屏、切换应用后持续定位的交付证据。地图 Provider 选择、设备权限和后台运行方案需在实现阶段确定。

## 验收场景

1. 两台设备分别以本单客户与师傅登录：师傅开启共享并移动，客户地图更新位置与时间。
2. 师傅关闭后，客户地图撤去位置；延迟上传、订阅重连、刷新页面不能恢复已撤销的位置共享。
3. 未授权、其他客户、其他订单、跨租户访问或上传均被服务端拒绝。
4. 拒绝设备定位权限、定位超时、断网、旧坐标及乱序更新有明确状态；不显示虚构位置、路线或到达时间。
5. 订单取消、完成和授权到期后停止共享。重新开启需要师傅明确操作。
6. 客户与师傅互发文字，跨设备送达；断网重试不重复插入消息，定位开关不影响联系。
7. 前台、后台、锁屏分别记录测试结果；桌面浏览器测试不能替代手机后台验证。
